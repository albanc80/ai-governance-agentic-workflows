Technical Implementation Specification

Engineering Guide: Agentic Governance Framework for Energy & O&G

1. System Architecture & Data Flow

The system must implement a Middleware Proxy between the LLM and the Tool Execution Layer.

Execution Flow:
LLM $\rightarrow$ Proposal $\rightarrow$ Governance Proxy (Logic Check) $\rightarrow$ (HITL/PVS if required) $\rightarrow$ Signed Request $\rightarrow$ Tool Execution $\rightarrow$ Response $\rightarrow$ Audit Log.

1.1 The Governance Proxy Logic

The Proxy must execute the following check for every tool call:

function evaluate_governance(action, context) {
    const assetClass = get_asset_class(context.asset_id);
    const isForbidden = check_forbidden_list(action, assetClass);
    
    if (isForbidden) return { status: "DENIED", reason: "Action prohibited for this asset class" };
    
    const confidence = context.model_confidence;
    if (assetClass === "CRITICAL") return { status: "PENDING", requirement: "TIER_3_PVS" };
    if (assetClass === "OPERATIONAL" && confidence < 0.90) return { status: "PENDING", requirement: "TIER_2_HITL" };
    
    return { status: "APPROVED", requirement: "NONE" };
}

2. Security & Identity Implementation

2.1 HSM-Signed Requests

To prevent "Prompt Injection" from triggering unauthorized physical actions, the proxy must sign requests using a Hardware Security Module (HSM).

Requirement:

  • Tool execution endpoints must reject any request lacking a valid HSM signature.
  • The signature must include the action_id, timestamp, and approver_id.

2.2 Air-Gap Proxying

Agents controlling ICS/SCADA must communicate via a Data Diode or a strictly controlled jump-host. No direct TCP/IP routing from the LLM environment to the industrial network.

3. PVS Implementation (Physical Verification)

Implementation of the "Safety-Valve" Protocol for Critical Assets.

PVS State Machine:

STATE: PROPOSED $\rightarrow$ (Trigger PVS) $\rightarrow$ STATE: AWAITING_VERIFICATION $\rightarrow$ (Field Engineer Sign-off) $\rightarrow$ STATE: VERIFIED $\rightarrow$ (Execute Tool) $\rightarrow$ STATE: COMPLETED.

API Endpoint: POST /pvs/verify

Payload: { "action_id": "uuid", "engineer_id": "uuid", "verification_token": "hash", "timestamp": "iso8601" }
